# Plan #3

Intent as read: a play-book (the decision procedure) and its run-book (the steps) that countersign-system
runs to verify its own integrity, strictly level by level — L1 unit-test code, L2 integration-test code,
L3 unit-invariant inference, L4 system-invariant inference — each level gating the next.

## Design
Gate: level N runs only when N-1 passed. A failure stops the run, is reported as found (detect, don't
dispose) and escalates as one explicit counter-prompt; nothing is repaired inside a diagnostic. Every
step is read-only; the one write is the diagnostic record, `agent-corpus/audits/<date>-self-diagnostic.md`.
Order is cost and confidence: cheap mechanical proof first, so inference budget is never spent on a
broken build.

| level | what is verified | how | mode (CIM) | pass |
|---|---|---|---|---|
| L1 unit-test code | each module's own tests | `dyad check --tests <root>` over the tests classified `unit` | automatic | every unit test OK |
| L2 integration-test code | modules together: scratch-repo installs, the four-zone end-to-end test, guards on the live tree, transaction guards, the evidence block | the tests classified `integration`, then `dyad check --guards` and `dyad check --evidence` | automatic | all OK, evidence block green, its sha recorded |
| L3 unit-invariant inference | does each unit's invariant list actually capture its contract? | first the mechanical invariant pass (`[invariant]` lines, all `ok`); then the Agent reads a rotating sample of K units (module docstring and owning Rule vs its `INVARIANTS` and tests) and judges coverage | implicit | no uncovered contract clause; each gap is a proposed invariant (a `backlog` row), not a fix |
| L4 system-invariant inference | properties of the whole system | a fixed list: CIM I1–I8 (the projector checks I1, I7, I6; the rest by reading); ledger ↔ provenance faithfulness (a sample, beyond the count check); zone and profile agree with the host (`infrastructure/HOST.md` vs observed); Rule-5 coherence (a rotating pair sample); hand-over criteria H1–H5 status; the sentinel | implicit | no violated invariant; each finding is an escalation |

Budget: L3/L4 inference is bounded per run (K units, P rule pairs), with a rotation cursor kept in the
record so successive runs cover everything — the client's inference-budget concern (#143) made explicit.

## Revision 2 (2026-10-06, after `N: … coded rules and prose claims … falsify` and `Y` to the model)

### The model (C1–C6, recorded in the reply of 2026-09-25)
Two categories of check, both required: a **coded check** (a test, guard or invariant — mechanical,
re-runnable, cheap) and a **prose claim** (a sentence the system asserts, checked by reading *against a
written attack*; a claim with no attack is not a check). The category is how a thing is checked, not
what is checked: a coded check may examine prose (`rules.py` block counts, `vocabulary.py`,
`references.py`), a prose claim may examine code (contract coverage). A prose claim confirmed on
successive runs is a candidate for code (Rule-13): the record proposes it, which is the CIM's codify
edge. "Coded rule" is not used: in this corpus a Rule is prose.

### The four levels are the grid
| | coded check | prose claim (with its attack) |
|---|---|---|
| **unit** | **L1** unit tests | **L3** each unit's contract covered by its invariants and tests |
| **system** | **L2** integration tests, guards on the live tree, transaction guards, evidence block | **L4** CIM I1–I8, coherence, ledger faithfulness, host agreement, H1–H5, sentinel |

Order: coded before prose, unit before system within each — L1, L2, L3, L4; each gates the next.

### Level contents
- **L1 — unit × coded.** Test classes classified `unit` in `self-diagnostic-levels.txt`, run through the
  runner (`dyad check --tests <dotted target>`). Pass: all OK.
- **L2 — system × coded.** Test classes classified `integration` (scratch repos, installs, the four-zone
  end-to-end test); then `dyad check --guards` (includes the coded checks of prose: Rule blocks,
  vocabulary, references, provenance counts, zones, manifest); then `dyad check --evidence`, its sha
  recorded. Pass: all OK.
- **L3 — unit × prose.** Opens with the coded invariant pass (all `[invariant]` ok). Then, for a rotating
  sample of K units, the claim "this unit's invariants and tests cover its stated contract" is read
  against the attack "name a contract clause no invariant or test would catch breaking". Each named
  clause is a finding → a proposed invariant/test (backlog row). A clause found covered on 2 runs → a
  codify candidate is not needed (already code); a contract clause only checkable by reading twice → a
  codify proposal.
- **L4 — system × prose.** A fixed claim list, each with its attack, e.g.:
  | claim | attack |
  |---|---|
  | I1 only a human countersigns | find a ratifying act whose recorded disposer is not the Operator (projector I1 is the coded half) |
  | ledger ↔ provenance is faithful | for P sampled rows, find a `disposed` entry whose provenance text does not carry that answer |
  | host record matches the host | find a kernel component whose observed version or presence differs from `infrastructure/HOST.md` |
  | the Rules are coherent | for a rotating pair sample, find a trigger on which two Rules instruct differently |
  | hand-over H1–H5 status is as recorded | find an H whose stated status the corpus contradicts |
  | the frame loads | the sentinel is absent from the session's report |
  Pass: no attack succeeds; each success is an escalation (one explicit counter-prompt).

### The record (`agent-corpus/audits/<date>-self-diagnostic.md`)
Per level: result, evidence (commands' outputs or the evidence sha), findings; for L3/L4 a table
`claim | attack | result | codify?` and the rotation cursor (next K units, next P pairs/rows).
